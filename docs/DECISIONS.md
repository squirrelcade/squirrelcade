## Details

**D03, stack.** Chosen because the old system's tested logic is JavaScript and carries over with its tests; one language for server and web; Fastify and Drizzle are typed and light; Mantine has the dense tables and forms an *arr-style interface needs; npm workspaces keep `node_modules` flat, which matters with Windows long paths disabled on the development PC. Alternatives: C# (like Sonarr, reads Playnite's LiteDB natively) or Python (like RomM).

**D04, no deployment.** Deploying means a new container on the home server, a Cloudflare Tunnel route and an Access application. Those are changes to shared infrastructure, so they wait for the user.

**D05, test data.** The NAS folder `Spreadsheet Backups` holds workbook exports up to 2026-08-14 (newer weekly backups aren't there). That copy predates rules WR-039 to WR-051 and the phase 11–12 tabs, which is fine for development.

**D07, workbook upload.** Downloading the workbook as .xlsx has a flaw: Excel limits tab names to 31 characters, and tabs whose shortened names collide are dropped from the file. In the 2026-08-14 backup that loses the NES Master Catalog and four Super Nintendo tabs. Gamefolio restores the full names of the tabs that survive and lists the missing ones. The lost tabs need another route (see STATUS.md).

**D08, not-in-catalog.** Adding every owned product to the catalog would count compilations and special editions ("Mass Effect Trilogy") as catalog games and inflate completion. Listing them lets the user link, add or ignore each one; on the 2026-08-14 data that's 137 PS3 products and a handful elsewhere.

**D09, revised.** The old gap tabs (the old system's missing lists) never listed a game the user owns only as a Japanese or PAL copy: Super Mario 64, Super Smash Bros., Pokemon Snap and two more on N64, Eastward on Switch, Armored Core 4 and For Answer on 360, Judgment and PaRappa on PS4, Wii Play. With home-region-only counting, Gamefolio called all of them missing. With other regions counting, N64 agrees 100% and the other consoles' differences fall to a handful. The phrase "any North American physical copy" in the old notes was about editions, not regions.

**D10, look-alikes.** The rule behind the suggestions: one title contains the other ignoring spaces ("HAWX" / "Tom Clancy's H.A.W.X"), or every word of the shorter title is in the longer ("Beijing 2008" / "Beijing Olympics 2008"). On the real data this turns the known false gaps (Cars 2, EndWar, HAWX, Beijing 2008, Rise of the Argonauts) into review questions; PS3 had 69 in total, 33 after the D21 and D22 rules (45 across all consoles, most of them the same game under another name, such as "Madden NFL 07" / "Madden 2007").

**D15, barcode lookups.** Free barcode databases rarely know which game and platform a UPC is, so a lookup only suggests a product name; the matching game is always picked by you, then stored in Gamefolio's own barcode table (shared by nothing else). UPCitemdb's trial needs no key; if it's down or over its daily limit, Store Mode says so and title search still works.

**D16, notifications.** The old emails came from n8n's SMTP node. Pushover was added because the home lab already uses it (the nightly container updates send their messages there), and it's the simplest reliable phone push. Summaries skip the list on the very first import ("4,043 games imported") and stop long lists at 100. Wishlist changes compare against a snapshot saved at each import; the last 30 are kept.

**D17, secrets at rest.** Encrypting them would need a key stored next to the database, which protects little on a single-user server. Sonarr and Radarr store their keys the same way. The /config folder (and its backups) should be treated as private.

**D18, where it runs.** Since the plan was written, every public service and n8n moved to the new Docker host, and the tunnel's only connector runs there. Port 7575 is free on it. Pulling the private image needs a GitHub token that can only read packages, which the user creates and types on the host.

**D19, publishing.** Building on the host would need access to the private repository; a registry keeps the host simple and lets the nightly updater pull new versions. Publishing stays a deliberate step until the user decides otherwise (for example, publishing on every push to main).

**D20, IGDB.** Downloading whole platform lists (500 games per request, about 4 requests a second) takes minutes for all catalog platforms, where searching title by title would take an hour and hit the rate limit. IGDB genres become the wishlist's genre names in a fixed order, most specific first (RPG, Platformer, Fighting, Racing, Sports, Rhythm / music, Visual novel, Point-and-click, Puzzle, Strategy, Shooter, Beat 'em up, Simulation, Party, Arcade, then Action-adventure), so a game IGDB files under Adventure and RPG counts as an RPG however many points each genre has. Horror themes make Horror; RPG styles come from the developer's country (Japanese: JRPG, otherwise Western RPG) or from Hack and slash (Action RPG) and Tactical (Tactical / strategy RPG). Titles are guessed from only when neither the user, the workbook nor IGDB gave a genre. Once IGDB data arrives, wishlist scores will move; the first import summary afterwards lists the biggest moves.

**D21, same-title rules.** Found with the comparison page: on PS3, 47 of the 54 games Gamefolio alone listed as missing or to review were these spelling differences ("The Elder Scrolls V: Skyrim" / "Elder Scrolls V: Skyrim", "Dragon Age 2" / "Dragon Age II", "Spider-Man 3" / "Spiderman 3", "NASCAR 2014" / "NASCAR 14"). PS3 agreement with the old system went from 80.7% to 95.1%, and five old false gaps were fixed (EndWar, H.A.W.X and H.A.W.X 2 on PS3; Marvel's Spider-Man 2 and WitchSpring R on PS5). No new false matches appeared. The rules apply only when comparing titles; stored keys are unchanged. "Mega Man X" and "Mega Man 10", "Tekken 3" and "Tekken 3D" stay different.

**D25, physical first.** Measured against the user's curated lists: Wikipedia's lists match them closely on consoles without download stores (PS2: 1,809 games against 1,833), but run far over on the newer ones (Switch 4,399 against 2,530, Xbox One 3,048 against 1,056), because those pages include download-only games without marking them. IGDB marks a physical release for about half to two-thirds of the curated games on the newer consoles (Switch 56%, PS4 60%, Xbox One 61%, Series X 57%, PS5 47%, Switch 2 almost none yet), and when it marks one, it's right. Other sources were ruled out: Wikidata is too sparse, Nintendo's site forbids scraping, the console stores sell downloads so they can't say what's physical, and PriceCharting's terms don't allow its data in software others use (D24). A user's own list fills the rest; the old workbook's Master Catalog tabs, downloaded as CSV, work as they are. Under a list, Wikipedia adds only newer games because adding every game it has brought in mostly the same games under other names (Wikipedia's "Madden NFL 2004" is PriceCharting's "Madden 2004") and, on PS3 and Xbox 360, unmarked download titles: 491 extra PS3 games and 830 extra Xbox 360 games on the user's lists. Store Mode answers "Need it if physical" for such a game, since a copy on the shelf settles the question.

**D22, editions.** The workbook's own ownership rules say "any owned edition satisfies the canonical game" and "edition variants count unless explicitly excluded", and the old system never listed the Wii U Just Dance Gold Editions as missing. **D27, RomM links.** Asked for by the user with the design, on 2026-09-27. RomM 5.3's API gives each ROM its IGDB id, platform, regions and tags (read from the file name), and whether it's playable in the browser only as a filter, so the index reads each mapped platform's ROMs (1,000 a request) and then the ids of its playable ones in one request. RomM's own "find by IGDB id" returns one ROM on any platform, which is why matching goes by IGDB id and platform in Gamefolio's index instead. An owned game finds its IGDB game through its own title or the names of the catalog game it counts as (which include IGDB's), since PriceCharting's titles often differ from IGDB's ("Zelda Link to the Past"). Links go to RomM's public address when one is set (Settings > Sources), while Gamefolio reads RomM on the local network. The title fallback compares only titles in the Latin alphabet whose key has more than one character: normalizing drops Japanese script, so a Japanese name of Tony Hawk's Pro Skater 2 and RomM's "デッドオアアライブ2" (Dead or Alive 2) both became "2" and one game was linked as the other (fixed the same day, after the first read of the user's RomM). The same check found owned Japanese releases whose PriceCharting title leaves out the subtitle No-Intro's file names carry ("Rockman 7" for "Rockman 7 - Shukumei no Taiketsu! (Japan)"): when the title finds nothing, the file name's title up to " - " counts, as a possible match, but only when the ROMs it finds are one game (the same file title, or the same IGDB game), so a series name alone ("Dragon Ball Z") links to none of several games. Editions in brackets ("[Not for Resale]") are left out of the comparison too.

**D35, catalog sources in the user's order.** Asked for by the user on 2026-09-27, after the Game-Key Card research (see "Where Game-Key Card marks come from" in docs/PLAN.md): the public sources that build the lists should be listed in a setting, with a priority the user can change for when they conflict, and the building done inside Gamefolio. The model: each source lists games (by its own rules) and states facts about them (other names, release dates, formats, proof of a physical release, what to collect). Which games a catalog has stays as before: your list's games always; a public source adds every game where there's no list, and under a list only games that came out after it (or were announced without a date), unless Settings > Catalogs says every game. A game is the same game across sources by any of its names, its name without an edition ("Absolum - Nintendo Switch 2 Edition" is "Absolum") or the same IGDB game; within one public source only the same name (a list page naming a game twice), and your own list's rows stay as they are. Sources that can't be read keep the games they brought; a source that's off brings none. The Docker image builds it in a .NET stage as a self-contained Alpine binary. A reading replaces the library (games gone since stay, inactive); ownership is worked out when read, so a settings or audit change applies at once. Against the old system's PC Library tab (the same backup), every storefront's counts agree except two EA and Ubisoft games the old system's exact-string comparison missed in the audit ("Dragon Age II", "Splinter Cell: Conviction" written with other punctuation). The audit matches the exact title, not the title without its edition: "Mass Effect Legendary Edition" is not "Mass Effect" (an earlier try did match editions, and got 10 EA games wrong). Games are grouped by title without edition marks for the page and the console copies, so a different game with the same title (SimCity on PC and on the Super Famicom) shows as related, never as owned.

**D39, the PC wishlist.** The old system built a candidate pool of 1,500 to 2,000 games from public Steam store searches (a tag search per genre, sorted by reviews), the owner's public Steam wishlist, series expansion, new releases and sealed physical copies, and ranked a 300-game PC wishlist with the console factors plus Steam review quality and +25 for a sealed physical copy without a PC copy. Gamefolio keeps the idea and most of the sources, but searches IGDB: its API is official and already configured, a genre search is one request for 100 games, and IGDB links each game to its Steam app, so Steam is only asked for review summaries (store.steampowered.com/appreviews, no key, about one request a second, at most 300 per search). Steam's share of positive reviews stands for the game's reviews from 50 reviews on (IGDB's rating below that), trusted by count as on the console wishlist. A title search for a sealed console game keeps only the result with the same title (editions aside), so "Hollow Knight" never brings "Hollow Knight: Silksong". Not carried over for now: the owner's Steam wishlist (the old system had no address for it) and a "new and notable" source. The defaults (100 games, +15 sealed, −15 subscription) are neutral; the owner's old values were 300 games and +25.

**D40, Japanese titles romanized differently.** Built overnight on 2026-09-27 from docs/PLAN.md's open item, with the user's standing approval. PriceCharting writes long vowels out ("Jikkyou", "Yakyuu", "Daishuugou") where Wikipedia writes macrons ("Jikkyō", "Yakyū", "Daishūgō"), so on the Super Famicom such copies matched nothing and weren't even suggested. On the development copy the Super Famicom went from 149 to 154 of its 1,460 games owned (one of them through IGDB's other name for a game), and 4 more pairs became Review questions (a shortened title written with long vowels, for example). The rule matches automatically only on catalogs of Japanese releases because the same folding would make "Soul" and "Sol" alike: there it's a question. Titles whose subtitle PriceCharting leaves out ("Doraemon 2" for "Doraemon 2: Nobita no Toys Land Daibouken", 22 more of the Super Famicom's 57 unmatched copies) stay Review questions: counting them automatically would break the rule that a look-alike is never a match, and waits for the user's say. Stored keys (the PC library's family keys, the wishlist's) don't change.

**D41, sets.** Built overnight on 2026-09-27 from docs/PLAN.md's "Later: Collections", with the user's standing approval. The plan called them Collections; in the app they're Sets, because the menu already has Collection (what you own) and "set" is how collectors talk about a publisher's line ("the Limited Run set"). Taking ownership from the console catalogs, instead of matching a set's titles again, keeps one answer per game: a review answer, a mapping or an edition rule given on a console's page counts in every set. Wikipedia has "List of Limited Run Games releases" (564 games on 2026-09-27 with a console Gamefolio knows, 164 rows without one, mostly PC releases and rows with no console in the list); Super Rare Games has no list page, so it would be a CSV. On the development copy the Limited Run set is 66 of its 739 console releases owned (Switch 52 of 177), and 5 missing games have an owned look-alike (PriceCharting's full titles, where the list leaves the subtitle out). Wikipedia writes "(Xbox)" for Limited Run's newer Xbox releases, so 9 games land on the original Xbox. Store Mode, the wishlist's set points, answering a look-alike on the set's page ("Same game" or "Not it"), games added by hand or taken out, and "You have it on ..." for a missing game came the same night; answers and hand edits are kept when the list is read again.

**D42, titles without their subtitle.** Built overnight on 2026-09-27 as the setting offered earlier ("an automatic short-title rule"), left off because it breaks the rule that a look-alike is never a match until the owner says otherwise. Measured on the development copy with the owner's collection: on consoles of Japanese releases it counts 37 more Super Famicom games (154 to 191 of 1,460), takes the Review questions there from 78 to 35 and the unmatched copies from 52 to 15, and adds 1 on the Nintendo 64 (Japan); all 37 checked by hand, other names included ("Rockman 7" is Mega Man 7 through its Japanese title). A first version took a copy's edition off before comparing and so counted "Overcooked [Special Edition]" as "Overcooked: All You Can Eat"; the whole title has to be the start now. Two catalog games that start the same way ("UFO Kamen Yakisoban: ..." and its prize edition) stay a question, and so does a subtitle holding a number the copy lacks ("Pachinko Fan: Shouri Sengen 2").

**D45, Store Mode without a connection.** Built overnight on 2026-09-28 with the user's standing approval. Stores, flea markets and conventions are where Store Mode is used and where phones often have no signal, and until now a search there failed. The copy is the server's own answers (the same code as a search, run for every game), so offline answers match online ones; the phone ranks a typed title with the same function as the server. It's on by default because the owner uses Store Mode on their phone and the copy is their own data in their own browser; it's a setting because a shared computer shouldn't keep it, and signing out removes it. Without a service worker, the page itself doesn't load with no connection at all: Store Mode has to be open (or the app loaded, which fetches Store Mode's code in the background) before the signal goes. A service worker could lift that, but a faulty one keeps serving old files, so it waits for testing on the owner's phone. "I bought it" works without a connection: the purchase is kept in the browser (removed on sign-out with the copy) and sent when Gamefolio answers again (when Store Mode opens, when the browser is back online, or after a search that reached it); marking a game bought twice counts it once, so a purchase sent twice is harmless. Notes and new barcodes need Gamefolio and wait for the connection.
